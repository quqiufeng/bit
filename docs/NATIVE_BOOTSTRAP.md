# Linux native bootstrap

## Current fixed point

The native path is:

```text
A1 seed
 -> C0v2 seed
 -> compiler-bootstrap.c
 -> c1-bootstrap.elf
 -> compiler.c / runtime.c
 -> final native Linux C1
 -> c1l (standalone linker built from linux/standalone-*.c)
 -> stage1 -> stage2
```

The two-stage step exists because the capacity-extended `compiler.c` is too large
for the old upstream C1 limits.  C0v2 builds a bootstrap C1 from
`compiler-bootstrap.c` (the frozen C1 source with only the allocator limit
raised), and that bootstrap C1 then compiles the final, capacity-extended
compiler and runtime.

`stage1` and `stage2` are byte-identical.  The path is exercised by
`bootstrap/linux/c0/native-c1.sh` and by `./build.sh`.

The only committed binary seed is `bootstrap/linux/seed.elf`.  A0 and A1 are
materialized on demand from text seeds into the build directory:

- `bootstrap/linux/seed.elf` / `seed.hex` (trusted binary root)
- `bootstrap/linux/a0/a0.seed.hex` -> A0 via `a0/from-hex.sh`
- `bootstrap/linux/a1/a1.seed.hex`
- `bootstrap/linux/c0/c0.seed.hex` (materialized on demand) -> A1 via `a1/from-hex.sh`
- `bootstrap/linux/c0/c0v2.a1`
- `bootstrap/linux/c0/native/compiler-bootstrap.c`
- `bootstrap/linux/c0/native/compiler-runtime.c` (generated/verified combined source)

The native linker used for stage1/stage2 is now `c1l.elf`, built by C0v2/A1
from `linux/standalone-runtime.c`, `linux/standalone-link.c` and
`bootstrap/linux/c0/native/linker-helpers.a1` (A1 syscall stubs).  It reads output, entry and
object paths as a line-based manifest on stdin.  The committed linker seed is
still decoded and compared against the source-built linker, but it is not
invoked to link any executable.

The script no longer invokes Windows PE, `pe2elf`, `build/c1link`, C1-built
A1, a host C compiler, or Python.

## C1 `-E` mode

C1 now accepts `-E`:

```sh
c1 -E source.c > source.i
```

The implementation deliberately does not touch include-file state.  Includes
are loaded into the single `pp_input` arena and switched through
`pp_file_cursor[]` / `pp_file_end[]`; the stable output point is the final
`source[]` written by `pp_put` during `preprocess()`.

After `preprocess()`:

- on failure, return 1;
- in `-E` mode, write `source[0..size)` with `source[i] & 255` to stdout and
  return 0;
- otherwise continue with `position = 4096; next(); ...`.

The output is a token stream, not a byte-for-byte replacement for a host
`cpp -E`: comments and original whitespace are not preserved and no `#line`
markers are emitted.

## Remaining seed work

The next reductions are:

1. `compiler-bootstrap.c` is the C0v2 input: frozen stable C1 source with the
   global allocator limit raised.  `compiler-runtime.c` remains generated by
   `native/make-seed-source.sh` for provenance and hash checking, but the active
   native path uses `compiler.c` + `runtime.c` compiled by `c1-bootstrap.elf`.
2. The native linker synthesizes `_start` and the `__c1_sysv_*` stubs directly
   as a text section with symbols and relocations; `startup.seed.o` /
   `syscalls.seed.o` are gone.
3. The source-built standalone linker now links the native chain.  The next
   step is to drop `linker.seed.hex`, its hash entry, and the cross-check from
   the native script.
4. Remove the remaining host `gcc`/`ld` and upstream PE bridge from the global
   `build.sh` seed chain.
